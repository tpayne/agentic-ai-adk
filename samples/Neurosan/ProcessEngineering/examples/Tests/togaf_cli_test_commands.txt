# ============================================================
# TOGAF architecture artifact generation robustness test script

# Run from samples/Neurosan/ProcessEngineering:
#   uv run python cli.py -f examples/Tests/togaf_cli_test_commands.txt
#
# Exercises TOGAF_Pipeline, TOGAF_Compliance_Agent (internal, never called directly), and
# TOGAF_Scenario_Tester end to end: nothing-saved negative cases (generate/regenerate/update/
# what-if, each against a genuinely clean slate), a real creation run against a saved design
# document (default "both" variant), the Phase H / capability-maturity scope disclosure, what-if
# scenario queries that trace the generated traceability/dependency links, all four regeneration
# phrasings (implicit "both", explicit vision-only, explicit definition-only, and explicit "vision
# and definition" wording -- mirrors design_hld_lld_split_cli_test_commands.txt's own design_variant
# coverage exactly), an explicit update request proving TOGAF_Agent's UPDATE branch preserves
# unrelated content, a requirements-only source path (no design document saved at all, confirming
# the design-takes-precedence rule doesn't make requirements-only generation impossible), and
# domain-crossover disambiguation between TOGAF_Scenario_Tester and Design_Scenario_Tester.
#
# Test fixture: a small inline design-document brief, written by this script itself (same
# "Supplier Onboarding Service" + "Finance System integration" scenario rm_rtp_cli_test_commands.txt's
# own Part C2 RtP offering already describes) -- deliberately reused so the resulting TOGAF content
# genuinely supports togaf_scenario_tester.hocon's own two sample_queries ("What happens if we
# deprioritize the Supplier Onboarding capability?" / "What is the impact of removing the Finance
# System integration?"), rather than those sample queries being untestable against a differently-
# themed fixture.
#
# Session state in this CLI is a mix of in-memory conversation (reset by "clear") and on-disk saved
# JSON (output/design_data.json, output/requirements_summary.json, output/togaf_data.json,
# independent of "clear"). The $ resets below delete the on-disk state at specific points so the
# nothing-saved negative cases, and the requirements-only path in Part G, are exercised against a
# genuinely clean slate rather than leftover state from an earlier part of this same script.
#
# UNLIKE this project's other *_cli_test_commands.txt scripts, this one calls "clear" between every
# Part boundary from Part B onward. CONFIRMED NECESSARY from a real run: Part B's own design
# creation is itself a large, multi-agent generate/review consortium whose conversation alone grows
# to several hundred thousand tokens, and every later turn in the SAME session resends that entire
# history as context even though TOGAF_Pipeline/TOGAF_Scenario_Tester read everything they need
# straight from disk (load_full_design_context/load_full_togaf_context), never from chat history.
# Chaining Part B directly into Part C without a reset made a real run appear to hang for several
# minutes on the TOGAF compliance loop's second iteration -- not an infinite loop anywhere in this
# codebase (confirmed: no unbounded loop exists in the TOGAF docgen/pipeline code; the saved
# cli.log showed real, if slow, forward progress right up to that point), but ordinary per-call LLM
# latency compounding badly against an unnecessarily large, functionally irrelevant prompt.
#
# This was compounded by a second, separate, now-fixed bug: config/llm_config.hocon's pipeline
# summarization middleware had drifted to an "openai:..." model while llm_config.model_name itself
# had moved to Gemini, so it silently required an API key (OPENAI_API_KEY) nothing else in this
# project needs -- see that file's own comment for the full story. After fixing both, a real run's
# TOGAF compliance loop (previously the hang site) completed in ~115 seconds, but Part D's own
# what-if queries THEN stalled for 20+ minutes instead -- on TOGAF_Scenario_Tester, a network with
# no loop and no middleware at all. cli.log confirms the model actually in use is
# "gemini-3-flash-preview" (a preview-tier endpoint, typically a tighter per-minute quota than GA),
# and the stall landed immediately after Parts B/C's own combined ~750,000-token burst -- consistent
# with provider-side rate-limiting, not a code defect (no unbounded loop or retry-without-logging
# path exists anywhere in this codebase, confirmed directly). The `sleep` pauses added after the
# heaviest exchanges below are a pragmatic smoothing measure for this, not a guaranteed fix.
#
# The SAME run also surfaced a third symptom, consistent with the same root cause: Part B's own
# design generation repeatedly emitted a malformed document_metadata.document_type value ('2' --
# plausibly the schema enum's own 0-indexed position for "Combined" leaking out instead of the
# string itself, a known tool-calling/structured-output quirk more common when the underlying model
# is under load) before eventually producing a VALID but completely unrelated design -- an
# "OmniChannel Retail Platform" (Stripe/Adyen payments, inventory/order/customer management) in
# place of the actually-requested "Supplier Onboarding Service" (an authenticated supplier portal
# integrating with a Finance System), despite the request's own explicit, itemized FR-/NFR-
# breakdown. This is a genuine content-grounding failure, not a thin/ambiguous-request bail-out --
# CONFIRMED and hardened against with a new explicit rule in both ports' own Design_Doc_Analysis_
# Agent instructions ("NEVER SUBSTITUTE A DIFFERENT SYSTEM/DOMAIN FOR THE ONE ACTUALLY NAMED"), but
# given the surrounding evidence (the same run's own malformed enum value, and the timing
# immediately after Parts B's own enormous token burst), this reads as the same underlying
# provider-side degradation manifesting as lower output quality rather than only latency -- the new
# instruction is a real, additional safeguard, not a guaranteed fix for an inherently probabilistic
# failure mode.
# ============================================================

$ rm -f output/design_data.json output/requirements_summary.json output/togaf_data.json output/cloudarch_drawio.xml
