# ProcessEngineering Python UML

These Mermaid diagrams document the Python declarations under
`process_agents/` and `tests/`:

- [Class inventory](class-inventory.md) lists every class declaration with
  its source location and declared base.
- [Class hierarchy](class-hierarchy.md) shows all declarations and actual
  inheritance, including test fixtures.
- [Application class diagram](application-classes.md) focuses on the
  application classes, with useful members and source-supported composition.
- [ADK composition](adk-composition.md) shows the major runtime agent
  pipelines and their `SequentialAgent` / `LoopAgent` composition.

The hierarchy distinguishes project classes from external bases by labeling
the external package in each node. `Agent` is shown as the ADK-declared base
for `DefaultAgent`; the source documents `google.adk.agents.Agent` as an alias
of `LlmAgent`. Composition edges are included only where construction or
typed fields establish the relationship; agent names alone are not treated as
class relationships.

The inventory covers 61 `class` statements across application and test
Python files. No `@dataclass` declarations or enum subclasses were found.
Functions, module-level agent registries, and non-class data structures are
outside the class inventory. The Mermaid diagrams render on GitHub; no local
Mermaid/PlantUML renderer was available when these were prepared.

## Physical PNG diagrams

Rendered, standalone images generated by [`generate_diagrams.py`](generate_diagrams.py)
(pure matplotlib -- same approach as `process_agents/common/uml_diagram_agent.py`,
no Graphviz/PlantUML binary required). Re-run it after a structural change:
```
cd samples/GCP/ProcessEngineering && .venv/bin/python codeDoc/generate_diagrams.py
```

- [`class-diagram.png`](class-diagram.png) -- the same 13 application
  classes as [application-classes.md](application-classes.md), rendered as
  a physical UML class diagram (inheritance/composition/dependency arrows).
- [`sequence-cloudarch-pipeline.png`](sequence-cloudarch-pipeline.png) --
  full agent-level detail for `CloudArch_Pipeline` (generator / reviewer /
  stop controller), including the review `LoopAgent`'s loop frame.
- [`sequence-process-create.png`](sequence-process-create.png) /
  [`sequence-process-update.png`](sequence-process-update.png) /
  [`sequence-design-doc-create.png`](sequence-design-doc-create.png) /
  [`sequence-design-doc-update.png`](sequence-design-doc-update.png) --
  stage-level sequence diagrams for the other four pipelines. Each
  `LoopAgent` stage (review loop, JSON normalization loop) is shown as one
  collapsed lifeline whose label lists its internal agent order and
  iteration cap, rather than as separate lifelines per inner agent --
  see [adk-composition.md](adk-composition.md) for why those stages repeat
  nearly the same shape across all four pipelines.

Arrows in the sequence diagrams show execution order through the parent
`SequentialAgent`/`LoopAgent`'s `sub_agents` list, not literal Python method
calls between siblings -- the actual caller in every case is the ADK
orchestrator object, which is omitted as its own lifeline since it never
does anything but dispatch to the next child in order.
