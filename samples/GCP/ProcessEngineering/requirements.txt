# Compliance chokepoint: process_agents/ imports process_interface
# exclusively, never process_toolkit directly (see shared/process_interface's
# own module docstrings). The process_toolkit entry below stays anyway --
# NOT because process_agents/ needs it, but because process_interface's own
# pyproject.toml declares a bare "process-toolkit" dependency with a
# `[tool.uv.sources]` local-path override that only uv understands. Plain
# pip has no equivalent, so without this explicit local -e entry, `pip
# install -r requirements.txt` would try (and fail, confirmed directly) to
# fetch "process-toolkit" from PyPI, where it doesn't exist. Resolved
# relative to the CWD pip is invoked from, which must be this directory
# (matching this file's own documented `cd samples/GCP/ProcessEngineering
# && pip install -r requirements.txt` setup flow, and this Dockerfile's
# WORKDIR). Docker builds must use the repo root as build context so this
# path exists -- see the Dockerfile's own comments.
-e ../../../shared/process_toolkit
-e ../../../shared/process_interface
